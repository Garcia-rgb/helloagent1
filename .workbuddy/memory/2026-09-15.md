## 排障：LLM 自检报 APIConnectionError（关键发现）

用户填好两个 key 后跑自检：天气 ✅ / Tavily ✅ / **DeepSeek ❌ APIConnectionError**。

### 根因：本机 DNS 把 api.deepseek.com 解析到了不可达 IP

证据链：
| 项 | 结果 |
|---|---|
| 本机网卡 DNS 服务器 | `10.11.1.12`、`172.17.0.10`（**均内网地址**）、`114.114.114.114` |

### 排障方法坑（记下来别再踩）

- `requests` 的 `session.proxies = {"http": None, "https": None}` 配合 `trust_env=True`

- 沙箱里做网络诊断时，环境变量 `HTTP_PROXY/HTTPS_PROXY` 被强制指向 64996，

- `nslookup` 在 PowerShell 里输出编码会崩（UnicodeDecodeError / AttributeError），

- Python 输出中文时，跑 `Out-File -Encoding utf8` 会因 stdout 是 GBK 而乱码；
  加 `$env:PYTHONIOENCODING="utf-8"` 可解决。

## 教学：逐段精讲第 1 章代码（16:25）

用户提出「按每部分的代码来学」，从 `get_weather` 开始逐句讲。

### 实跑验证得到的事实（wttr.in 真实返回）

- `data` 顶层 4 个字段 **全部是 list**：`current_condition`(1) / `nearest_area`(1) / `request`(1) / `weather`(3)
- `data['current_condition'][0]` 是 dict，**21 个 key**（temp_C / humidity / wind / uvIndex / FeelsLikeC …）
- `weatherDesc` **又是 list**，原始样子 `[{"value": "Sunny"}]`，取 `[0]['value']` 才是 `'Sunny'`
- `weatherDesc` 返回**英文**；`temp_C` 是**字符串 `'29'` 不是数字**
- URL：`https://wttr.in/北京?format=j1` → requests 自动转义成 `%E5%8C%97%E4%BA%AC`
- `format=j1` 是拿到 JSON 的关键；去掉它返回终端彩色文本
- 响应耗时 **1.4~1.7 秒**（北京/上海）
- 城市名不存在 → **HTTP 500 + 纯文本 body `location not found`**
- 空城市名 → HTTP 200，wttr.in 按出口 IP 猜位置

### 关键纠正：我自己的一个错误结论（已查证推翻）

初次推断：`response.json()` 抛的 `JSONDecodeError` 两个 except 都接不住 → 会穿透。
**实测推翻。** `requests.exceptions.JSONDecodeError` 的完整 MRO：

```
requests.exceptions.JSONDecodeError
requests.exceptions.InvalidJSONError
requests.exceptions.RequestException      <- 它是 RequestException 子类！
builtins.OSError
json.decoder.JSONDecodeError
builtins.ValueError
```

→ 会被**第一个 except 接住**。所以教程那段 except 的覆盖面比字面大得多：
`ConnectTimeout / ReadTimeout / ConnectionError / ProxyError / HTTPError(4xx/5xx) / requests 版 JSONDecodeError` 全部走第一个分支。

**教训：requests 的异常层次不能凭直觉推断，必须打印 `__mro__` 验证。**

### 这段代码真实存在的三个问题（按严重度）

1. **`requests.get(url)` 没写 timeout** —— requests 默认 `timeout=None` = 永不超时。
   一旦 wttr.in 卡住，Agent 死在这一行且无任何输出。**这是唯一严重的一条。**
2. **错误信息不分类**：所有失败都报「网络问题」，模型无法区分「城市名错」和「网络断」，
   会做出错误的下一步决策（无意义重试 / 错误道歉）。
3. **无兜底 except**：`TypeError` 之类（如 `weatherDesc` 变成字符串，
   `"Sunny"[0]['value']` 就是 TypeError）不在两条 except 范围内，会穿透 → 工具抛异常 → Agent 崩。
   工具的硬性契约是**永不抛异常，任何失败都返回可读字符串**。

### 提到的工程版改法（5 处）
① 加 `timeout` 参数 ② `HTTPError` 单独接、带上 status_code ③ 接 `ValueError`
④ 兜底 `except Exception` ⑤ 网络请求与结构解析拆成两个 `try`
