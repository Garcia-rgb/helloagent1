## 四、排障：LLM 连不通（本篇重点）

自检结果：天气 ✅、Tavily ✅、**DeepSeek ❌ `APIConnectionError`**。

### 排查方法：三层分离

「连不通」可能是三层里任何一层出问题，混在一起查会互相干扰。所以分开测：

| 层 | 查什么 | 怎么查 |
|---|---|---|
| L1 环境变量代理 | `HTTP_PROXY` / `HTTPS_PROXY` 是否被注入 | 打印 `os.environ` |
| L2 DNS | 域名解析出的 IP 对不对 | 本机 `socket.getaddrinfo` 对比公共 DNS 的 DoH 结果 |
| L3 网络与本地端口 | IP 本身通不通、本地代理监听没有 | TCP 连接测试 |

### 结论：本机 DNS 把 `api.deepseek.com` 解析到了不可达的 IP

| 检查项 | 结果 |
|---|---|
| 本机网卡 DNS | `10.11.1.12`、`172.17.0.10`（**都是内网地址**）、`114.114.114.114` |
| 本机解析出的 IP | `101.71.73.135`、`123.148.116.184` → **443 端口全部超时** |
| 阿里 / 腾讯 / Google 公共 DNS | 一致给出 `183.131.191.171`、`115.231.230.218` → **31ms 就通** |
| 用公共 DNS 的 IP 直连（校验 SNI） | 证书 `CN=api.deepseek.com` 通过，**HTTP 200** |
| 带真实 key 调 `chat/completions` | 返回「通了」 → **key 完全有效** |

所以：**key 没问题、DeepSeek 服务没问题，是内网 DNS 返回了坏 IP。**

### 修法：改 hosts 固定节点

```
C:\Windows\System32\drivers\etc\hosts

# Hello-Agents: bypass poisoned internal DNS
183.131.191.171 api.deepseek.com
```

hosts 是受保护的系统文件，**需要管理员权限**。所以做成了 `tools\fix_deepseek_hosts.bat`：右键「以管理员身份运行」→ 自动备份 → 追加两行 → `ipconfig /flushdns`。

**回滚**：删掉那两行，或用备份文件 `hosts.ha-backup-20260915` 覆盖回去。

改完实测：

```
本机 DNS 解析: ['183.131.191.171']
[A] 直连   OK   通了
```

## 五、踩过的坑

| 现象 | 原因 |
|---|---|
| `session.proxies = {"http": None}` 挡不住代理 | 环境变量代理优先级更高，必须 `session.trust_env = False` |
| 沙箱里测 DeepSeek 永远失败 | 沙箱有自己的出网代理，按域名白名单放行，拦截了 DeepSeek |
| `nslookup` 在 PowerShell 里输出崩 | 改用 `Resolve-DnsName -Server <ip>` |
| Python 输出中文变乱码 | 加 `$env:PYTHONIOENCODING="utf-8"` |
| 某个公共 DNS 不通 | 本机 `119.29.29.29`、`1.1.1.1` 直连超时，只有 `223.5.5.5` 可用 |
