## 一、`get_weather`（第 29–57 行）

### 1. 导入与函数签名

```python
import requests

def get_weather(city: str) -> str:
    """
    通过调用 wttr.in API 查询真实的天气信息。
    """
```

其中：

- `requests` —— 第三方 HTTP 库
- `city: str` —— 入参，城市名，如 `"北京"`
- `-> str` —— 返回值类型，**必须是字符串**
- 三引号那段 —— 函数说明。后面框架会把它当「工具描述」拿给模型看

### 2. 拼 URL

```python
url = f"https://wttr.in/{city}?format=j1"
```

其中：

- `{city}` —— 城市名塞进 URL 路径。**中文不用自己转码**，requests 会自动把它变成 `%E5%8C%97%E4%BA%AC`
- `format=j1` —— 要求接口返回 JSON 格式。**不加这个参数，返回的是终端彩色文本**，`json()` 会报错
- `url` —— 拼好的完整地址字符串

### 3. 发请求

```python
response = requests.get(url)
```

其中：

- `response` —— 服务器返回的响应对象，此时**还没解析内容**
- 注意这里**没写 `timeout=`** —— requests 默认永不超时，接口卡住程序就永久停在这一行

### 4. 检查状态码

```python
response.raise_for_status()
```

其中：

- 作用 —— 状态码是 4xx / 5xx 就抛异常；2xx 什么都不做，继续往下走
- 为什么要有 —— 不加这行，下面 `json()` 会去解析一段错误提示页，报出的错让人看不懂

### 5. 解析 JSON

```python
data = response.json()
```

其中：

- `data` —— dict。顶层 4 个字段：`current_condition` / `nearest_area` / `request` / `weather`
- 这 4 个**每个都是 list**，哪怕里面只有 1 个元素

### 6. 三层下标

```python
current_condition = data['current_condition'][0]
weather_desc = current_condition['weatherDesc'][0]['value']
temp_c = current_condition['temp_C']
```

其中：

- `data['current_condition']` —— list，长度 1
- 接着的 `[0]` —— 取第一个元素，是个 dict，里面有 21 个字段（`temp_C`、`humidity`、`uvIndex`…）
- `current_condition` —— 只是给这个 dict **起了个短名字**，方便下面两行用。不是转换
- `['weatherDesc']` —— 又是 list，原始样子 `[{"value": "Sunny"}]`
- `[0]['value']` —— 真正取到值，比如 `'Sunny'`（英文）
- `weather_desc` —— 天气描述，字符串
- `temp_c` —— 温度，**字符串 `'29'` 不是数字 29**。要算数得先 `int()`

那两个 `[0]` 是这段唯一「不讲道理」的地方：`current_condition` 和 `weatherDesc` 都只有 1 个元素，却是 list。这是 wttr.in 沿用旧版天气 API 的历史包袱（一个字段可以挂多条多语言描述）。**记住：看到 `[0]` 就说明那层是 list，不管元素个数。**

### 7. 返回

```python
return f"{city}当前天气：{weather_desc}，气温{temp_c}摄氏度"
```

其中：

- `{city}` —— 是**调用时传进来的参数**，不是接口返回的。接口返回的规范化城市名在 `nearest_area` 里
- `{weather_desc}` `{temp_c}` —— 上面第 6 块取的两个值
- 整句 —— 工具交给模型的「观察结果」，自然语言

### 8. 异常处理

```python
except requests.exceptions.RequestException as e:
    return f"错误：查询天气时遇到网络问题 - {e}"
except (KeyError, IndexError) as e:
    return f"错误：解析天气数据失败，可能是城市名称无效 - {e}"
```

其中：

- `e` —— 异常对象，`{e}` 会打出它的文字说明
- 第 1 个 `except` —— 覆盖**超时 / 连不上 / 4xx / 5xx / JSON 解析失败**
- 第 2 个 `except` —— 只覆盖两种情况：JSON 里**没有这个字段名**（`KeyError`），或**字段是空列表**（`IndexError`）
- 两个都 `return` 字符串、不 `raise` —— 工具抛异常会让整个 Agent 循环直接崩掉

## 二、实测补充：wttr.in 的真实行为

| 情况 | 结果 |
|---|---|
| 正常城市 | HTTP 200，耗时 **1.4 ~ 1.7 秒** |
| 城市名不存在 | **HTTP 500** + 纯文本 body `location not found`（API 对参数错误回 500 而不回 400，不规范） |
| 空城市名 | HTTP 200，按出口 IP 猜位置 |

### requests 异常层次（实测 `__mro__`）

```python
requests.exceptions.JSONDecodeError
  → requests.exceptions.InvalidJSONError
    → requests.exceptions.RequestException     # 它是 RequestException 的子类
      → builtins.OSError
        → json.decoder.JSONDecodeError
          → builtins.ValueError
```

所以 `response.json()` 失败时**会被第一个 except 接住**，不会穿透。

> **教训**：requests 的异常层次不能凭直觉推断，必须打印 `__mro__` 验证。

## 三、这段代码的三个问题

| # | 问题 | 后果 |
|---|---|---|
| 1 | `requests.get(url)` 没写 `timeout` | 接口卡住时 Agent 永久停在这一行，没有报错、没有输出。**最严重的一条** |
| 2 | 错误信息不分类 | 城市名写错也报「网络问题」，模型无法区分「名字错」和「网络断」，可能做错误决策（无意义重试 / 错误道歉） |
| 3 | 没有兜底 `except` | `TypeError` 之类不在两条 except 范围内（如 `weatherDesc` 变成字符串，`"Sunny"[0]['value']` 就是 TypeError），会穿透 → 工具抛异常 → Agent 崩 |

工具的硬性契约：**永不抛异常，任何失败都返回可读字符串**。因为返回值会作为 Observation 喂回模型，模型就可能自己纠正——换个城市名重试，或者告诉用户「查不到这个城市」。

## 四、工程版改法（供参考）

```python
def get_weather(city: str, timeout: float = 10.0) -> str:
    """查询指定城市实时天气。永不抛异常，任何失败都返回可读的错误字符串。"""
    url = f"https://wttr.in/{city}?format=j1"
    try:
        response = requests.get(url, timeout=timeout)     # ① 加 timeout
        response.raise_for_status()
        data = response.json()
    except requests.exceptions.Timeout:
        return f"错误：查询 {city} 天气超时（{timeout} 秒无响应）"
    except requests.exceptions.HTTPError as e:            # ② 服务端错误单独接
        return f"错误：天气服务返回 {e.response.status_code}，城市名 {city!r} 可能无效"
    except requests.exceptions.RequestException as e:
        return f"错误：查询 {city} 天气时网络异常 - {type(e).__name__}"
    except ValueError:                                    # ③ 接 JSON 解析失败
        return "错误：天气服务返回了非 JSON 数据"
    except Exception as e:                                # ④ 兜底，守住契约
        return f"错误：查询天气出现未预期问题 - {type(e).__name__}"

    try:                                                  # ⑤ 解析单独一块
        cc = data["current_condition"][0]
        return f"{city}当前天气：{cc['weatherDesc'][0]['value']}，气温{cc['temp_C']}摄氏度"
    except (KeyError, IndexError, TypeError):
        return f"错误：天气数据格式不符合预期，城市名 {city!r} 可能无效"
```

改动的 5 个点：① 加 `timeout` ② `HTTPError` 单独接、带上 status_code ③ 接 `ValueError` ④ 兜底 `except Exception` ⑤ 网络请求与结构解析拆成两个 `try`。
